# 公版會計系統（generic-accounting-gas）

給一個企業體（集團）使用的會計系統：一個網址、一套帳號，右上角切換公司；每家公司的帳各自一份 Google 試算表，完全分開。
v0.1 是「帳本核心」：從科目、期初餘額、傳票，一路到損益表與資產負債表。
v0.2 加上多公司：公司管理、依公司設定權限、集團合併報表（每家一欄＋合併欄）、常用傳票範本。
v0.3 加上單據匣：拍照上傳發票／收據自動辨識、匯入財政部進項發票、確認後入帳並連結原始單據。
v0.4 強化單據辨識：OCR 原文另存、欄位來源標示、自動驗證（缺漏、金額、統編、重複、鎖帳）、扣抵人工判定、左右並排校正畫面、批次確認入帳。

## 單據匣（v0.3）

| 項目 | 說明 |
| --- | --- |
| 上傳 | 照片或 PDF，可一次選多張；手機上自動縮小成 JPEG（最長邊 2000 像素）再上傳，一張一張依序處理 |
| 文字辨識 | Google 雲端硬碟內建 OCR（免費，資料不出業主的雲端硬碟）；讀出日期、發票號碼、賣方／買方統編、未稅、稅額、總計 |
| 財政部匯入 | 電子發票整合服務平台下載的進項發票 CSV（UTF-8 或 Big5），依欄名對應；作廢、折讓自動略過；也支援手機條碼載具「M\|」格式 |
| 防重複 | 同一個發票號碼（拍照或匯入）只會有一筆，第二次標示「重複」 |
| 入帳 | 選付款方式 → 產生傳票（自動帶建議科目，有本公司統編的發票自動拆進項稅額）→ 對照原始單據確認後儲存 |
| 連動 | 傳票顯示「附單據」可看原檔；傳票作廢後單據回到「待處理」 |
| 權限 | 助理可上傳與查看；入帳、略過、匯入限會計與管理者 |
| 存放位置 | 集團主檔所在資料夾／會計單據／「公司代碼 公司名稱」；單據資料在各公司試算表的「單據」分頁 |

### v0.4 單據辨識強化

| 項目 | 說明 |
| --- | --- |
| 原文另存 | OCR 原始文字存在「單據原文」分頁（不截斷），「單據」分頁只放解析結果；規則更新後可「重新解析」，人工改過的欄位不會被覆蓋 |
| 欄位來源 | 每個欄位標示 原文／推算／匯入／人工；讀到的金額不互相覆蓋，對不上就警示 |
| 自動驗證 | 錯誤（不能入帳）：缺日期或總額、未稅＋稅額≠總額、日期在未來／早於開帳日／已鎖帳、同號發票已入帳。警示（入帳前要核對）：缺發票號碼或賣方統編、稅額不是 5%、統編檢查碼錯、買方不是本公司、同號發票另有單據、疑似重複、OCR 失敗或內容太少 |
| 扣抵判定 | 未判定／可扣抵／不可扣抵。系統依「買方＝本公司、一般稅額、統一發票、有稅額、科目非交際費等」給建議，**不會自動套用**；未判定不能入帳 |
| 校正畫面 | 左邊原始單據（手機上下排列），右邊可修改的欄位、問題清單、扣抵、科目、付款方式；兩人同時修改時後送出者會被拒絕（版本號） |
| 批次確認 | 清單勾選（有錯誤的不能勾）→ 選付款方式與扣抵方式 → 一次最多 20 張，每張都經過 `saveVoucher` 同一套檢查，一張失敗不影響其他張 |
| 新 API | `getDoc`、`updateDoc`、`reparseDoc`、`postDocs`（入帳一律經過 `postDocVoucher_` → `saveVoucherCore_`）；`restoreDoc` 改為必填原因 |
| 進項不得扣抵科目 | `NON_DEDUCTIBLE_CODES`（6211 交際費、6281 職工福利、6271 伙食費），正式使用前請記帳士確認 |

**升級到 v0.3／v0.4：** 推送程式後，用部署者（業主）帳號在 Apps Script 執行一次 `setup`，同意新增的「雲端硬碟、文件」授權，再按「部署 → 管理部署作業 → 新版本」。
用手動貼上版的話，還要在 Apps Script 左側「服務」按 ＋ 加入 **Drive API**（v3）；沒加也能上傳，只是不會自動辨識。

## 多公司架構（v0.2）

| 試算表 | 放什麼 |
| --- | --- |
| 集團主檔（程式綁定的那份） | 公司清單、帳號、各公司權限、操作紀錄；同時也是第一家公司的帳 |
| 各公司試算表 | 公司設定、會計科目、期初餘額、傳票、期間、月底盤點、單據、單據原文、科目參考庫 |

- 集團管理者：進入所有公司，可新增公司、管理帳號與權限、看集團報表。
- 一般成員：逐家公司指派角色（管理者／會計／助理）。
- 新增公司：在「公司管理」按「新增公司」，系統自動建立試算表（放在集團主檔同一個資料夾）、依產業帶入建議科目。
- 集團報表：損益表、資產負債表每家公司一欄，最後一欄為合併數；目前尚未沖銷公司間往來。
- 傳票範本：`src/15_Templates.js`，依公司產業顯示；含稅範本只要輸入含稅金額，自動拆未稅與 5% 稅額。
- 從 v0.1 升級：推送新程式後，在 Apps Script 執行一次 `setup`（會要求新增「雲端硬碟」授權，用來建立新公司的試算表），原本的試算表自動成為第一家公司，舊的會計／助理帳號自動改成該公司的成員。

## 第一期功能

| 功能 | 說明 |
| --- | --- |
| 公司設定 | 公司名稱、統編、產業類別（可複選）、營業稅類型、會計年度起始月、開帳日 |
| 會計科目 | 內建「科目參考庫」（通用／餐飲／食品製造／食品買賣），依產業一次帶入，後台可篩選、加入、新增自訂、停用 |
| 期初餘額 | 開帳日的資產、負債、權益餘額，即時檢查借貸平衡 |
| 傳票 | 收入／支出／轉帳傳票，多行分錄、往來對象、借貸平衡檢查、修改、作廢（號碼不重複使用）、複製 |
| 月底盤點 | 定期盤存：輸入各存貨盤點金額，自動產生成本調整傳票；重做時自動作廢舊傳票 |
| 帳簿 | 日記簿、分類帳（可依往來對象看明細分類帳） |
| 報表 | 試算表、損益表（可比較上一期或去年同期、占營收%）、資產負債表（自動帶入本期損益） |
| 期間鎖帳 | 月結鎖帳；鎖帳前檢查試算平衡；只有管理者能解鎖且需填原因 |
| 權限 | 管理者／會計／助理三種角色，權限在伺服器端檢查 |
| 稽核 | 所有新增、修改、作廢、鎖帳、登入都寫入操作紀錄 |
| 寫入試算表 | 報表可一鍵寫到試算表「報表_」分頁，業主可直接在試算表查看 |

## 部署到一家公司（業主自己的 Google 帳號）

**方法 A：手動貼上（不需要任何工具）**

1. 業主建立一個新的 Google 試算表，命名例如「公版餐飲 會計系統」。
2. 上方選單「擴充功能」→「Apps Script」。
3. 把預設的 `程式碼.gs` 內容全部刪掉，貼上 `dist/Code.gs` 的內容。
4. 左側「檔案」旁的「＋」→「HTML」，檔名輸入 `Index`，貼上 `dist/Index.html` 的內容。
5. 上方函式選單選 `setup` → 按「執行」→ 依畫面完成授權。
6. 下方「執行紀錄」會顯示 admin 的臨時密碼，請記下。
7. 右上「部署」→「新增部署作業」→ 類型選「網頁應用程式」→ 執行身分「我」、存取權「所有人」→ 部署 → 複製網址。
8. 打開網址，用 admin 和臨時密碼登入，第一件事到「變更密碼」。

**方法 B：clasp 推送（開發者用）**

```
npm i -g @google/clasp
clasp login
clasp create --type sheets --title "公司名稱 會計系統" --rootDir src
clasp push
```

**更新程式：** 改完程式後，在 Apps Script「部署」→「管理部署作業」→ 鉛筆 →「版本」選「新版本」→ 部署。網址不變，已開啟的頁面重新整理即可。

## 第一次使用（管理者）

1. 「公司設定」：公司名稱、產業類別、營業稅類型、開帳日。
2. 「會計科目」→「科目參考庫」→「依公司產業一次加入建議科目」，再停用用不到的、新增自訂科目。
3. 「期初餘額」：輸入開帳日當天的餘額，借貸要平衡。
4. 「帳號管理」：幫會計、助理開帳號（臨時密碼只顯示一次）。
5. 開始記傳票；月底做「月底盤點」→ 看報表 →「期間鎖帳」。

忘記 admin 密碼：打開試算表 → 上方選單「公版會計系統」→「重設 admin 密碼」。

## 測試

```
npm test                                   # 帳務流程測試（模擬試算表，不需 Google 帳號）
node tests/ui/build-preview.js             # 產生可離線操作的預覽頁 tests/ui/preview.html
node tests/ui/check-ui.js                  # 三種角色 × 桌機／手機逐頁檢查與截圖
node tests/ui/check-docs.js                # 單據匣：校正畫面 → 扣抵判定 → 入帳 → 批次入帳 → 異常分頁（桌機／手機）
node tools/build-dist.js                   # 產生 dist/ 手動貼上版
```

預覽頁示範帳號：admin / Admin1234、acct / Acct12345、helper / Help12345（只存在於預覽頁）。

## 注意事項

- 科目參考庫是範本，正式使用前請記帳士或會計師確認科目與稅務處理。
- 月底盤點採定期盤存；若回頭修改已盤點月份之前的進貨，之後月份的盤點需重新儲存一次。
- 手寫單據的辨識結果一定要人工對照確認；金額或日期沒讀到時，入帳畫面會提醒自己填。
- 年度結帳、合約上傳、營業稅申報資料在後續期別加入。
